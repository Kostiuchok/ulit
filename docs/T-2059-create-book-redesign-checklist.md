## 2. Відкриті питання — ВІДПОВІДІ ОТРИМАНО (Анатолій, 2026-08-17)

1. ✅ Upsell-блок праворуч — **не прибирати, переписати текст**: "замовити переклад книжки, який знадобиться для публікації там і там..." — прямо пов'язано з новою фічею **T-2064** (переклад книги, ШІ + платний перекладач-людина). Посилання/дія цього блоку веде на функціонал T-2064, коли той буде готовий.
2. ✅ Автозаповнення автора — **з профілю автора** (`User.name`), не з метаданих файлу.
3. ✅ "або введіть адресу вашого сайту" — **прибрати згадку URL з тексту**, не в scope.
4. ✅ Стрілки гортання обкладинки — **легкий preview кількох готових шаблонів**. Анатолій готує шаблони сам як PNG/JPG-файли (фонове зображення), під які **програмно** позиціонуються блоки з текстом (назва/автор/підзаголовок). **Ці самі шаблони входять і в повний список шаблонів у редакторі обкладинки** (`CoverDesignerCanvas.tsx`) — тобто один спільний набір даних "шаблон = фонове зображення + координати текстових блоків", використовуваний і тут (легкий preview), і там (повний редактор). Блокується на наданні файлів Анатолієм — код структури готувати заздалегідь, самі PNG/JPG додати пізніше.
5. ✅ Місце у вайзарді — **новий об'єднаний крок 0**, що заміняє поточні step===0/step===1 `BookWizard.tsx`; Ціна/Розповсюдження/Огляд — без змін.
6. ✅ Формати — **приймати doc/docx/rtf/odt/txt, pdf НЕ обіцяти** для звичайного (структурованого, редагованого) шляху імпорту. **Але додатково**: якщо книга вже професійно зверстана й готова у форматі PDF — дати автору **окрему можливість опублікувати її як є**, у ЙОГО власному розмірі сторінки, без проходження через наш редактор/пагінацію. Це прямий аналог "ПРО-акаунта" Ridero і варіанту (А) з T-2057 — окремий upload-шлях "у мене вже є готовий PDF", паралельний до структурованого імпорту docx/rtf/odt/txt, не заміна йому. Той самий шлях обслуговує і LaTeX-сценарій (T-2061).
7. ✅ Миттєвий чіп — **клієнтський стан, до фактичного HTTP-завантаження**, підтверджено.

## 3. Технічний блок-радіус (де саме будуть зміни, коли питання вище вирішені)

- `apps/web/app/dashboard/books/new/page.tsx` + `apps/web/components/books/BookWizard.tsx` (кроки 0/1) — новий об'єднаний UI
- Новий компонент живої 3D-обкладинки з кількома преднастроєними шаблонами (легший за повний `CoverDesignerCanvas.tsx`, чи підмножина його ж рендер-логіки — уточнити при коді, не зараз)
- `apps/api/src/modules/books/upload.ts` — розширити `ALLOWED_DOCX_MIME`/перевірку розширення на doc/txt/rtf/odt(/pdf?); `validateDocxPageSize` (T-2057) наразі парсить `word/document.xml` — для не-docx форматів ця перевірка технічно неможлива в тому ж вигляді (rtf/odt/doc мають інакшу внутрішню структуру за форматом) — окремо продумати чи взагалі валідувати розмір сторінки для не-docx форматів, чи тільки для docx
- `apps/worker/src/jobs/import-manuscript.ts` — гілки конвертації за розширенням файлу (пряме читання Pandoc для odt/rtf/txt, LibreOffice pre-convert для doc, окреме рішення для pdf)
- `apps/worker/src/lib/pandocToEditorDoc.ts` — імовірно без змін (працює з Pandoc JSON AST незалежно від вихідного формату файлу)
