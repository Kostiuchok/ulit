# План: пакет "все для Книжкової палати" одним кліком (ISBN + УДК + авторський знак)

> Задача: у адмінці, на сторінці книги, одна кнопка має зібрати всі дані та файли, необхідні для подання книги в Книжкову палату України — щоб адмін міг одразу завантажити і передати далі.

## Контекст і дослідження

Досліджено офіційну "Інструкцію про порядок надання Міжнародного стандартного номера книги (ISBN) в Україні" (Книжкова палата, 2020, `docs/instr_isbn.pdf` — уже є в проєкті) та сторінки ukrbook.net (`agentstvo.html`, `UDC_poslugy.html`). Реальний механізм відрізняється від інтуїтивного уявлення "заявка на кожну книгу окремо":

- **ISBN не подається по кожній книзі окремо.** Книжкова палата видає видавцю (ULIT) цілий **блок** наперед розрахованих номерів; далі сам видавець призначає конкретні номери конкретним книгам (§8.2, §8.4 Інструкції). Це збігається з тим, що вже реалізовано: адмін вручну вписує ISBN у `PATCH /api/admin/books/:id/book-chamber`.
- **УДК + авторський знак подаються РАЗОМ, по кожному виданню**, як єдина послуга "шифр зберігання" (`UDC_poslugy.html`: "Шифр зберігання складається з класифікаційних індексів УДК та авторського знака"), листом на `udc2920054@ukr.net`, тема листа: `"УДК, найменування замовника"`. Онлайн-форми немає.
- **Послуги ББК на сайті КП взагалі немає** — узгоджується з тим, що користувач сам зазначив: ББК поступово виходить з ужитку. Поле `bbkCode` лишаємо як є (опційне, вручну), не займаємось.
- Висновок: ISBN і УДК/авторський знак — це два запити до **однієї й тієї самої** інституції, яким потрібні по суті **одні й ті самі** дані по книзі (назва, повне ПІБ автора, анотація, сам рукопис для класифікації, обкладинка). Це один пакет, не дві окремі фічі.

### Що вже реалізовано (виявлено при дослідженні коду)

`apps/api/src/modules/admin/book-chamber.ts` уже має `GET /api/admin/books/:id/isbn-package` + `.../annotation.txt`, з гейтом `isIsbnReady()` (потрібні: анотація, ПІБ автора, обкладинка, printPdfUrl). Показується на двох сторінках адмінки (`/admin/isbn-queue` і `/admin/books/[id]/distribute`) як **3 окремих посилання, які треба клікати по черзі** ("Файл 1/2/3"), а не одне завантаження.

### Конкретні прогалини

1. Відповідь пакету не містить самих значень `isbn`/`udcCode`/`bbkCode`/`authorSign`, `genre`, `language`, `printPageCount` — саме те, що потрібно мати під рукою для листа на УДК-пошту.
2. Немає `backCoverUrl` (тільки передня обкладинка `coverUrl`).
3. Це 3 кліки, не 1, і нічого не запаковано в один файл для вкладення в лист.
4. Колофон рукопису (`apps/web/components/manuscript/frontMatter.ts`, генерується один раз при першому імпорті рукопису) друкує текст `ISBN {isbn}`/УДК/ББК на момент генерації — а ISBN/УДК/авторський знак майже завжди призначаються **пізніше**, вже після модерації, через `book-chamber.ts`. Тобто включений у пакет `printPdfUrl`, як правило, матиме ці поля **порожніми**. Автоматичне виправлення цього — окрема велика задача (зачіпає live-редагування рукопису); у цьому плані лише показуємо адміну попередження, щоб це не було сюрпризом.

## Backend — `apps/api/src/modules/admin/book-chamber.ts`

**1. Розширити `GET /api/admin/books/:id/isbn-package`** — додати у select/відповідь: `isbn`, `udcCode`, `bbkCode`, `authorSign`, `genre`, `language`, `printPageCount`, `backCoverUrl`. Існуючі поля (`title`, `authorFullName`, `annotationTxtUrl`, `manuscriptPdfUrl`, `coverUrl`) лишаються без змін.

**2. Розширити генерацію `annotation.txt`** (той самий роут) — додати жанр, мову, кількість сторінок і (якщо вже присвоєно) ISBN/УДК/ББК/авторський знак. Формат лишається plain text, той самий `Content-Disposition: attachment`.

**3. Новий ендпоінт `GET /api/admin/books/:id/isbn-package.zip`** — одне автентифіковане завантаження, що пакує все в один ZIP, за тим самим патерном `archiver` + `minio.getObject`, який уже є в `admin.ts` (масовий ZIP дистрибуції, `admin.ts:720-758`: `import archiver`, `ZipArchive`, `archive.append(stream, {name})`, `archive.finalize()`). Гейт — той самий `isIsbnReady()` (400, якщо не готово — як і зараз). Вміст:
   - `заявка.txt` — розширений текст із пункту 2
   - `рукопис.pdf` — з `book.printPdfUrl` (стрім з MinIO)
   - `обкладинка-перед.<ext>` — з `book.coverUrl`
   - `обкладинка-зад.<ext>` — з `book.backCoverUrl`, лише якщо є

   Розширення файлу обкладинки визначати з ключа об'єкта (`path.extname()`), запасний варіант — `.jpg`.

Змін у Prisma-схемі не потрібно — усі поля вже є на `Book`.

## Frontend

**`apps/web/app/admin/isbn-queue/page.tsx`** і **`apps/web/app/admin/books/[id]/distribute/page.tsx`** (обидві вже отримують `isbn-package`):

- Додати основну кнопку **"⬇ Завантажити пакет (ZIP)"**, яка тягне `.../isbn-package.zip` за тим самим патерном автентифікованого завантаження, що вже є для `annotation.txt` (`downloadAnnotation()` в `isbn-queue/page.tsx:39-58` — fetch з bearer-токеном → blob → object URL → синтетичний клік по `<a download>`). Це стає головною дією.
- Існуючі 3 окремих посилання лишити як другорядні/"або окремо" — зручно для швидкого перегляду в браузері без розпакування.
- Оновити текст-підказку: пакет тепер покриває **ISBN + УДК/авторський знак** разом, і показати точний формат теми листа з дослідження: *"Надішліть УДК-заявку на udc2920054@ukr.net, тема листа: «УДК, [назва видавця]»"*.
- Додати попередження про можливо застарілий колофон/штрихкод: якщо `book.isbn` (або `udcCode`) уже присвоєно — показати нотатку: *"Переконайтесь, що рукопис і обкладинка показують актуальний ISBN/УДК — вони фіксуються на момент створення, а не оновлюються автоматично після присвоєння"*, з посиланням на редактор рукопису / обкладинки.

## Свідомо поза межами цього етапу

- **Автоматичне оновлення колофону/штрихкоду на обкладинці** при пізньому присвоєнні ISBN/УДК — реальна прогалина, але потребує зміни live-контенту рукопису й флоу збереження в редакторі обкладинки; занадто велике для цього етапу, замість цього — попередження в UI.
- **Поле "вид видання" (нове/перевидання)** — стосується §8.7–8.9 Інструкції (чи потрібен новий ISBN при повторному виданні), але в моделі ULIT немає окремого поняття "видання", відмінного від самого рядка книги; лишається на розсуд адміна, не окреме поле в БД.
- **ББК** — жодного живого сервісу КП для цього не знайдено; `bbkCode` лишається опційним/ручним, без змін.
- **Окремий ISBN на кожен формат** (палітурка/обкладинка/PDF/EPUB/FB2 — §3.3/§8.15 Інструкції формально цього вимагають) — модель ULIT "один ISBN на книгу" це свідоме спрощення, яке вже діє; не переглядається тут.

## Перевірка

- `pnpm --filter api exec tsc --noEmit` після змін у `book-chamber.ts`.
- `pnpm --filter web exec tsc --noEmit` і `pnpm --filter web build` після змін у двох сторінках адмінки.
- Вручну: на книзі, що проходить `isIsbnReady`, відкрити `/admin/isbn-queue`, натиснути нову кнопку ZIP, перевірити, що архів містить усі 4 файли (або 3, якщо немає задньої обкладинки) з правильним вмістом; повторити з `/admin/books/[id]/distribute`. Також перевірити, що помилка 400 для не готової книги досі коректно спрацьовує (існуюча поведінка, не повинна зламатись).
