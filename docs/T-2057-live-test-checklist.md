# T-2057 — чекліст живого тесту (ручна перевірка на проді)

> Мета: закрити пункт "Живий тест" з `docs/T-2057-checklist.md` — перевірити серверний рендер друкованого PDF на РЕАЛЬНІЙ книзі через задеплоєний пайплайн (WeasyPrint), не на синтетичному тесті. Позначай `[x]` по факту, з коротким коментарем "ок" / "не ок + що саме" поруч.

## Як дійти до передперегляду

Кабінет автора → книга з уже завантаженим і імпортованим рукописом → редактор рукопису → кнопка "Передперегляд" (або посилання в сайдбарі) → `/dashboard/books/:id/manuscript/preview`.

Якщо книга ще не має `manuscriptContent` (рукопис не імпортовано в редактор) — спочатку відкрий книгу в редакторі рукопису хоча б раз, щоб запустився імпорт.

---

## 1. Базовий флоу

- [х] Перше відкриття сторінки передперегляду показує індикатор "Формуємо друкований PDF…" з відсотком прогресу
- [х] За ~10-60 секунд (залежно від обсягу тексту) індикатор змінюється на реальний PDF у вікні перегляду
- [х] PDF видно ПРЯМО на сторінці (не просто посилання) — можна скролити/гортати сторінки всередині вбудованого перегляду
коментар: в передпергляді пдф - немає стрілок гортати стоірнки. виправити

## 2. Розмір сторінки

Подивись жанр книги на сторінці "Вихідні дані" → знайди його в таблиці нижче → це і є очікуваний розмір сторінки в PDF.

| Жанр | Очікуваний розмір |
|---|---|
| Проза, Драматургія, Наук. фантастика, Фентезі, Детектив, Роман, Повість, Оповідання, Мемуари, Інше | 130×200мм (Стандартний) |
| Поезія | 107×177мм (Кишеньковий) |
| Нон-фікшн, Бізнес, Самодопомога | 145×215мм (Енциклопедичний) |
| Дитяча | 170×240мм (Збільшений) |

Реальний розмір у PDF дивись через властивості документа в PDF-переглядачі (в Chrome/Edge — меню "⋮" над відкритим PDF → "Властивості документа"; в Adobe Reader — File → Properties → Description).

- [-] Розмір сторінок у PDF відповідає жанру книги за таблицею вище
Розмір книжки має бути перед очима, поруч із Жанром, або там же це доцілдьно. Тим паче на скріншотах рідеро видно, мають бути обовязково в розділі Вихідні дані. Не розумію, чому це не реалізовано, хоча про це я писав і давав скріншоти як має бути. Може проблема в тому що тобі простіше робити по вайрофреймам? Я очікую одне, а результат геть інший 

- [х] Пропорції сторінки на око відповідають очікуваному формату (не A4, не квадрат)

## 3. Структура документа (форзац/титул)
Передперегляд в сайдбарі живе своїм життям а передперегляд із рукопису своїм життям. Два Передперегляди. Я вже писав, про те що вони мають злитися в один. Чому не реалізовано?

- [ ] Перша сторінка PDF — порожня (службовий форзац)
- [ ] Друга сторінка — титул (назва, автор, підзаголовок)
- [ ] Третя сторінка — зворот титулу (УДК/ББК/анотація/ISBN/© — якщо ці дані є в книзі)
- [ ] Якщо в рукописі є присвята — вона йде окремою сторінкою після звороту титулу

## 4. Розділи (chapter) — старт з правої сторінки

- [ ] Кожен розділ (стиль "Розділ" у редакторі) починається на непарній (правій, recto) сторінці PDF
- [ ] Якщо перед розділом інакше вийшла б парна сторінка — WeasyPrint сам вставляє порожню сторінку перед ним (звір номери сторінок: розділ завжди на непарному номері)
- [ ] Заголовок розділу видно зверху першої сторінки цього розділу

## 5. Епіграф

- [ ] Абзац зі стилем "Епіграф" — сам, окремо, на власній сторінці (не ділить сторінку з іншим текстом)
- [ ] Сторінки одразу до і після епіграфа теж не мають чужого тексту напроти нього (епіграф ізольований з обох боків)

## 6. Текстові стилі

Перевір, що кожен стиль, застосований у редакторі, візуально відрізняється у PDF так само, як у самому редакторі (шрифт/розмір/вирівнювання):

- [ ] Розділ — великий, по центру, великими літерами
- [ ] Секція/підрозділ — помітно менший за розділ, теж по центру
- [ ] Заголовок / підзаголовок — виділені, але не як розділ/секція
- [ ] Звичайний текст — вирівняний по ширині, з відступом першого рядка
- [ ] Цитата — курсив, зсунута/з рамкою зліва
- [ ] Вірш — по центру, з переносами рядків як в оригіналі (не злитий в один абзац)
- [ ] Підпис — курсив/дрібніше, вирівняний праворуч

## 7. Зображення

- [ ] Зображення з вирівнюванням "ліворуч"/"праворуч" в редакторі — обтічні текстом з відповідного боку і в PDF
- [ ] Зображення "по центру" — окремим блоком по центру
- [ ] Розмір зображення в PDF пропорційний до того, як воно виглядало в редакторі (не розтягнуте/не обрізане неочікувано)

## 8. Ручні розриви сторінок

- [ ] Якщо в рукописі вручну вставлено "Розрив сторінки" (кнопка в редакторі) — у PDF на цьому місці реально починається нова сторінка
- [ ] Сірий пунктир/підпис "Розрив сторінки" (видимий тільки в редакторі) НЕ з'являється в друкованому PDF — розрив "невидимий", просто реальний перехід на нову сторінку

## 9. Номер сторінки та колонтитул

- [ ] Номер сторінки внизу — на місці, яке вибрано в налаштуваннях (зліва/по центру/справа — перевір, яке значення збережено для цієї книги)
- [ ] Наскрізна нумерація без пропусків/дублів від початку тіла книги до кінця
- [ ] Зверху сторінок (крім перших/службових) видно назву поточного розділу (running header)

## 10. QA-кнопка "Завантажити PDF"

- [ ] Кнопка/посилання "Завантажити PDF (QA)" видно у верхній панелі поруч із кнопкою "До редактора рукопису", коли PDF готовий
- [ ] Відкриває/завантажує ТОЙ САМИЙ файл, що показаний у вбудованому перегляді (звір розмір файлу або просто відкрий і порівняй кілька сторінок)

## 11. Оновлення після редагування

- [ ] Заходиш у редактор, вносиш будь-яку зміну в текст, зберігаєш
- [ ] Повертаєшся на сторінку передперегляду — вона знову показує "Формуємо PDF…" (а не стару версію), і після завершення видно ЗМІНЕНИЙ текст у PDF
- [ ] Якщо НІЧОГО не міняти і просто повторно відкрити передперегляд — PDF показується одразу, без повторного очікування (використовується вже готовий файл, не перегенеровується даремно)

## 12. Крайні випадки

- [ ] Книга без завантаженого/імпортованого рукопису — сторінка передперегляду показує зрозуміле повідомлення ("спочатку завантажте рукопис"), не зависає і не падає з помилкою
- [ ] Дуже короткий рукопис (1 розділ, кілька абзаців) — PDF все одно коректно формується, без помилок

## Якщо щось не ок

Запиши: номер пункту → що саме побачив (краще зі скріншотом) → на якій книзі (посилання/id) відтворюється. Це піде як конкретний баг-репорт, а не загальне "щось не так".
