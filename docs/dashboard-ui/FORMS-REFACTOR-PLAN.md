# План: форми кабінету автора без милиць

Дата: 2026-10-05. Статус: **чернетка плану, чекає рішень власника** (розділ 7).
Реліз Альфи відсунуто до завершення цього плану (рішення власника 2026-10-05).

## 1. Мета

Сторінки «Вихідні дані», «Ціна та розповсюдження», «Огляд» і редактор обкладинки
поводяться однаково й передбачувано:

- автор завжди бачить, **яке поле не заповнене** і чому;
- автор завжди бачить, **який блок змінено і не збережено**;
- **збереження або проходить повністю, або не проходить взагалі**, і причина видна біля поля;
- **вийти зі сторінки з незбереженим неможливо мовчки**;
- сервер і сторінка **не можуть розійтись** у тому, що вважається «заповнено».

## 2. Що не так зараз (підтверджено наживо 2026-10-05)

| # | Симптом | Причина |
|---|---|---|
| 1 | Вкладки не перемикаються | Панель збереження отримує стан «поштовхами» після кожного перемалювання; нестабільне значення контексту дало нескінченний цикл, який блокував переходи |
| 2 | Анотація 188 символів не підсвічена, сервер відхиляє | Правило «магазини → мінімум анотації» жило лише на сервері; сторінка підсвічувала за власною копією умов |
| 3 | Ціна збереглась, магазини — ні | Два окремі запити; другий упав після того, як перший застосовано |
| 4 | «Зберегти» неактивне, а підсвіченого поля немає | Умови «можна зберігати» і «що підсвітити» написані окремо |
| 5 | Змінений блок не позначено | Частина полів у формі, частина поза нею з ручними прапорцями |
| 6 | Вихід зі сторінки губив зміни; потім вікно не переходило | Перехоплення кліків по всьому документу поверх «м'якого» переходу |
| 7 | Дашборд показував ✓ там, де вкладка — «не виконано» | Власне, слабше визначення «заповнено» |

Пункти 1, 2, 4, 5, 7 сьогодні залатано; 3 і 6 — частково. План прибирає самі причини.

## 3. Схема

```
packages/shared-types
  bookRules.ts ── один опис правил ─────────────────────────────┐
     поле → блок, «заповнено?», текст підказки,                  │
     залежні правила (магазини → мінімум анотації)               │
                                                                 │
apps/api                                   apps/web              │
  PATCH /api/books/:id/output-data ◄──────  useBookForm(блоки) ◄─┘
   · перевіряє ТИМИ САМИМИ правилами         · одна форма на сторінку
   · зберігає все або нічого                 · «змінено» = поточне ≠ збережене
   · помилка = { поле, текст }               · «не заповнено» = правило з shared-types
                                             │
                     ┌───────────────────────┼────────────────────────┐
                     ▼                       ▼                        ▼
              підсвічування            панель збереження        охоронець виходу
          (рамка + підказка,         (читає стан форми,       (питає форму: «є
           мітка «Змінено · N»)       нічого не штовхає)       незбережене?»)
```

Редактор обкладинки й рукопису — не форми, але віддають той самий інтерфейс:
`hasUnsaved()`, `save()`, `canSave()`. Охоронець виходу один на весь кабінет.

## 4. Правила, які не порушуються

1. Одне правило — одне місце (`shared-types`). Сервер і сторінка його лише викликають.
2. «Змінено» обчислюється порівнянням зі збереженим. Ручних прапорців немає.
3. Усі поля сторінки — в одній формі. Поза формою нічого не редагується.
4. Одна дія «Зберегти» — один запит, одна транзакція.
5. Кнопка «Зберегти» неактивна **лише** тоді, коли на екрані є підсвічене поле з поясненням.
6. Спільний стан передається підпискою, не оновленням після перемалювання.
7. Помилка сервера завжди прив'язана до поля і показана біля нього та в панелі.

## 5. Етапи

Кожен етап закінчується робочим продом; наступний не починається, поки попередній не прийнято.

### Етап 0 — зафіксувати поведінку тестами (0,5 дня)
- Тести на правила в `shared-types`: кожне обов'язкове поле, мінімум анотації для кожної комбінації магазинів.
- E2E на чернетці: порожнє поле → підсвічено; зміна → «Змінено»; вихід → вікно; збереження → чисто.
- **Приймання:** тести зелені на поточному коді (або явно червоні там, де зараз помилка).

### Етап 1 — правила в одному місці (0,5 дня)
- `bookRules.ts`: поле → блок → правило → підказка; залежні правила.
- Сервер (`book.ts`, `distribution.ts`, `publish.ts`) і сторінки читають лише звідти.
- **Приймання:** видалення будь-якого правила ламає і серверний тест, і підсвічування.

### Етап 2 — одне збереження (0,5 дня)
- Ціна + магазини + знижка — один маршрут, одна транзакція, помилка з назвою поля.
- **Приймання:** закоротка анотація → нічого не збережено, підсвічено магазин і поле.

### Етап 3 — одна форма на сторінку (1 день)
- «Вихідні дані»: автори, біографія, «над книгою працювали», ISBN — у ту саму форму.
- «Ціна»: гонорари, магазини, знижка — форма замість окремих станів.
- `useBookForm` віддає: значення, «змінено по блоках», «не заповнено по полях», `save()`.
- **Приймання:** жодного ручного прапорця «змінено» в коді цих сторінок.

### Етап 4 — панель збереження і охоронець виходу (0,5 дня)
- Панель підписується на стан форми. Ефект «після кожного перемалювання» видаляється.
- Охоронець: одна обгортка над внутрішніми посиланнями й переходами з коду + кнопка «Назад».
- Редактор обкладинки й рукопису підключені через `hasUnsaved/save/canSave`.
- **Приймання:** вихід через вкладку, сайдбар, кнопку, «Назад», закриття вкладки — всюди питає.

### Етап 5 — прибирання і приймання (0,5 дня)
- Видалити тимчасові рішення 2026-10-05 (перехоплення кліків, дублі умов, стандартний перехід вкладок, якщо м'який підтверджено).
- Чекліст ручної перевірки для власника; запис у журнал `CLAUDE.md`.

Разом: **3–3,5 дня** роботи з перевіркою на проді після кожного етапу.

## 6. Як перевіряється

- Автотести правил (кожне правило — окремий тест).
- E2E на окремій тестовій книзі-чернетці, не на опублікованих.
- Після кожного етапу — мій прохід по проду + короткий чекліст власнику.
- Модель: Opus (форми «Вихідні дані» і «Ціна» — найскладніша логіка кабінету).

## 7. Рішення, потрібні від власника

1. **Біографія автора.** Зараз збереження біографії в книзі переписує біографію в профілі. Лишити так чи зробити біографію книги окремою?
2. **Закоротка анотація для магазину.** Забороняти збереження (як зараз) чи зберігати все, крім цього магазину, з попередженням?
3. **Вихід з редактора обкладинки.** Для опублікованої книги «Зберегти й перейти» відправляє обкладинку на затвердження і запускає 90 днів. Пропонувати цю кнопку у вікні чи лише «Залишитись / Вийти»?
4. **Тестова книга.** Лишити постійну чернетку «ТЕСТ підсвічування» для автотестів на проді чи створювати й видаляти щоразу?
5. **Порядок.** Починати з «Ціни» (там зараз найболючіше — половинчасте збереження) чи з «Вихідних даних»?
