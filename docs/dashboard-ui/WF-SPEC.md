# WF-SPEC · ULIT · Дашборд книги, «Вихідні дані», «Ціна», «Обкладинка», «Огляд» · v1

HTML — референс; будувати на наявних компонентах/токенах apps/web. Desktop 1280 px.

## Мета
Опублікований автор за 5 секунд бачить: що з книгою зараз, що робити далі, ціни і як оприлюднити зміни. Прибрати шум (13 виконаних кроків, «скоро»-пункти, сірі активні послуги), зробити форму «Вихідних даних» з одним збереженням і зрозумілою повторною модерацією.

## Дашборд `/dashboard/books/[id]`
1. **Наступний крок** — верхня картка (зелений акцент): «Наступний крок · 13 з 13 — Публікація у магазинах», пояснення (терміни 3–10 робочих днів), primary-кнопка «Переглянути публікацію».
2. **Кроки згорнуті** в один рядок «✓ 12 з 13 кроків виконано» + «Показати/Згорнути»; поточний крок завжди видно окремим рядком із бейджем «в процесі».
3. **Назви виконаних кроків — у минулому часі**: «Книгу створено», «Рукопис завантажено», «Ціну встановлено», «Обкладинку додано», «Платформи розповсюдження обрано», «Огляд пройдено», «Надіслано на публікацію», «Вихідні дані заповнено», «Магазини та розмір роялті обрано», «Перевірку завершено», «Договір укладено».
4. **«Отримати УДК»** — явний бейдж стану: «в процесі» (amber) / «необов'язково» (сірий) / «отримано» (зелений).
5. **Дії в шапці**: «Редагувати» (outline) · «Сайт книги» (primary) · «⋯». Якщо є неопубліковані зміни — «Опублікувати зміни» стає primary (з лічильником змін), «Сайт книги» → outline.
6. **Меню «⋯»**: «Копіювати посилання на книгу», «Історія публікацій», роздільник, **«Зняти з публікації»** (danger, з поясненням; далі — діалог підтвердження).
7. **Банер змін** (лише стан «є зміни»): перелік змінених розділів + «Після «Опублікувати зміни» книга піде на повторну модерацію…», посилання «Що змінилось?».
8. **Ціни** — компактна картка з 3 плитками (Електронна / Друк, м'яка / Друк, тверда) над кроками, вище згину; «Змінити ціну» — посилання в шапці картки.
9. **«Зробіть книгу кращою»**: для опублікованої книги першим блок «Просування книги»; платні послуги — активні картки з ціною «від … ₴» і шевроном (не сірі); усі «Скоро» — один згорнутий рядок; видиме посилання «Усі послуги →».
10. **Сайдбар** 264 px (було ~200): короткі назви без обрізання («Перегляд книги», «Публікація», «Замовити тираж»), групи «Редагувати книгу / У магазинах / Реклама»; усі «скоро»-пункти згруповані внизу в «Скоро: ще 4 розділи» (розгортається).

## «Вихідні дані» `/dashboard/books/[id]/output-data`
1. **Єдина назва «Вихідні дані»** — у сайдбарі, першому пункті степера (замість «Інформація») і заголовку сторінки.
2. **Банер для опублікованої книги** (info): збережені зміни не йдуть у магазини одразу; оприлюднення — «Опублікувати зміни» на дашборді → повторна модерація; посилання «До дашборду книги».
3. **Sticky-панель внизу**: «← До дашборду книги» · стан · «Зберегти зміни». Одне збереження на всю форму, кнопку «Зберегти ISBN» прибрано (ISBN зберігається з формою).
4. **«Мова книги»**: «Потрібна для Amazon, Google Play» — helper під полем (не в лейблі).
5. **Анотація**: лічильник «257 / 500 · мінімум 120» + шкала прогресу з позначками 50 (D2D), 120 (УДК), 150 (Google Play), 250 (Amazon KDP), 500 (макс.); досягнуті — зелені; легенда-чипи під шкалою.
6. **Блок «Декларації»** одразу під анотацією: чекбокс ШІ + пояснення, навіщо.
7. Усі наявні поля збережено: Назва (лічильник 255), Підзаголовок, Анотація, Жанр, Розмір книги (+ helper розміру), Мова, Вікові обмеження; «Автори книги» (Прізвище/Ім'я/По батькові, фото URL/завантаження, Біографія, «+ Додати автора»); «Над книгою працювали» (Роль, Ім'я, «+ Додати»); «Авторське право / попередня публікація» (Рік, Власник, Номер свідоцтва, ISBN + helper, чекбокс підтвердження).

## Спільне для 03, 05–07
- Степер — посилання на сторінки (Вихідні дані → `output-data`, Обкладинка → `cover`, Ціна та розповсюдження → `price`, Огляд перед публікацією → `review`, Публікація → дашборд); поточний крок — темна «пігулка».
- Правила підсвітки однакові: помаранчева рамка (amber-400) + бейдж «Змінено · N» = блок зі змінами; змінене поле — помаранчева рамка; червона (red-500) = помилка валідації. Sticky-панель унизу: «← До дашборду книги» · стан · дії.
- Формат книги — один термін на всіх сторінках: **«Стандартний 130×200 мм»**.

## «Ціна та розповсюдження» `/dashboard/books/[id]/output-data/price` (05, `price.html?state=dirty|saved`)
1. Дві картки: «Продаж електронної книги» і «Друкована книга». Таблиці мають однакові колонки: **Магазин · Ваш гонорар · Ціна для читача · Умови**.
2. Е-книга: ULIT 100 → 142.86 грн; Draft2Digital 100 → 166.67 грн; Google Play — ціну не задає автор; **Amazon KDP — рядок disabled** з причиною «Недоступно для цієї мови — Kindle приймає лише друковані»; **KDP Select — disabled** з причиною «ексклюзивність 90 днів конфліктує з Draft2Digital і Google Play».
3. «Умови» — один рядок + ⓘ (повний текст у tooltip).
4. Друк: формат і кількість сторінок — read-only чипи («Стандартний 130×200 мм», «12 сторінок»). Замість прихованих вкладок — матриця 2×2 (Кольоровий/Ч/Б × М'яка/Тверда) з ціною для читача в ULIT: 374.29 / 517.14 / 150.00 / 292.86; поточний варіант позначено.
5. **Одне поле гонорару на канал** (у рядку таблиці); окреме поле «Ваш бажаний гонорар за примірник (ULIT)» прибрано.
6. `dirty` (гонорар 150 → 160): блок «Друкована книга» — помаранчева рамка + «Змінено · 1 поле»; поле гонорару — помаранчеве + «було 150 → 160 грн»; ціна «~~374.29~~ 388.57 грн» (у таблиці й матриці). Панель: «● Є незбережені зміни у 1 блоці · ULIT: нова ціна — одразу після збереження» + «Скасувати» + «Зберегти зміни». Блок «Що відбудеться після внесення змін» прибрано (злито в панель).
7. `saved`: «Збережено ✓ · 12:41», кнопка disabled, підсвітки немає.

## «Обкладинка» `/dashboard/books/[id]/output-data/cover` (06, `cover.html`)
1. Банер для опублікованої книги — як у 03.
2. Картка статусу: «✓ Обкладинку завантажено» + primary «Редагувати обкладинку» + secondary «Замінити файлом».
3. Превʼю поруч: е-обкладинка (мокап, ~170 px) і друкований розворот; перемикач «М'яка / Тверда» — одне превʼю за раз; підписи «Задня сторона · Корінець · Лицева»; легенда ліній: пунктир — згин, крапки — обріз.
4. Чекліст вимог (зелені ✓; приклад помаранчевого пункту «Текст на корінці: немає — для 12 сторінок корінець завузький для тексту»). **Перелік правил і числа — WF-заглушки, підтвердити.**
5. Sticky-панелі немає, поки немає змін; «← До дашборду книги» — посилання внизу.

## «Огляд перед публікацією» `/dashboard/books/[id]/output-data/review` (07, `review.html?state=published|changes`)
1. Read-only картки: «Вихідні дані», «Рукопис», «Обкладинка», «Ціна та розповсюдження» — у кожній посилання «Змінити» на свою сторінку.
2. Ціни й прибуток — **одна таблиця**: Варіант · Ціна для читача · Ваш прибуток · Магазин (Е-книга 142.86/100.00; м'яка кольор. 374.29/262.00; тверда кольор. 517.14/362.00; м'яка ч/б 150.00/105.00; тверда ч/б 292.86/205.00 — ULIT).
3. «Платформи: 1 обрано» → чипи магазинів («ULIT») + «Додати магазини» (→ `price`).
4. «Готовність до реєстрації УДК» — згорнуто в рядок «✓ 4 з 4 вимог виконано», розгортається; без посилання на `docs/isbn-udc-requirements.md`.
5. `changes`: блоки, змінені з останньої публікації (Вихідні дані, Ціна), — помаранчева рамка + «Змінено», змінені рядки з міткою «змінено» (ціна ~~374.29~~ 388.57, прибуток ~~262.00~~ 272.00 = 70% ціни, як в інших рядках); панель: «● Змінено 2 блоки з останньої публікації · зміни підуть на повторну модерацію» + primary «Опублікувати зміни (2)».
6. `published`: без CTA — лише «← До дашборду книги» і «✓ Усі зміни опубліковано».

## Стани
- Дашборд: `published` (усе опубліковано) · `changes` (є неопубліковані зміни, кроки розгорнуто для демонстрації) · `menu` (відкрите «⋯»). Також: модерація змін у процесі — замість кнопки «Опублікувати зміни» бейдж «На модерації» (наявний `RepublishPendingNote`).
- Вихідні дані: `dirty` — «● Є незбережені зміни у N блоках · M помилка» + чип «Перейти до першого» + активна «Зберегти зміни» (за наявності помилок — червоний лічильник помилок у кнопці; клік не зберігає, а скролить до першого поля з помилкою); блоки зі змінами — помаранчева рамка + бейдж «Змінено · N полів», змінені поля — помаранчева рамка + мітка «змінено»; блок із помилкою — червона рамка + бейдж «N помилка», поле — червона рамка + червоний helper (напр. «Обов'язкове поле, якщо вказано рік»); `saving` — спінер у кнопці; `saved` — «Збережено ✓ · 12:41», кнопка disabled; `error` — червоний текст помилки + кнопка активна. Валідація: при збереженні — скрол до першого поля з помилкою.
- Неопублікована книга: банер змін не показується; у шапці — наявна `PublishButton`.

## Мобільна поведінка (< 768 px)
- Сайдбар → off-canvas (кнопка `panel-left`). Шапка: назва + бейдж, під ними дії; «Сайт книги»/«Опублікувати зміни» на всю ширину, «Редагувати» переходить у «⋯».
- Дашборд — одна колонка: Наступний крок → Ціни → Кроки → Обкладинка → «Зробіть книгу кращою».
- Вихідні дані: степер — горизонтальний скрол; 2 колонки форми → 1; Прізвище/Ім'я/По батькові — стопкою; save-bar фіксований унизу (з safe-area), текст стану скорочено до «● Не збережено» / «✓ Збережено».

## Критерії приймання
1. На 1280×800 вище згину видно: назву+статус, дії, «Наступний крок», ціни, рядок «12 з 13 кроків».
2. Виконані кроки згорнуті за замовчуванням; розгортання показує назви в минулому часі; поточний крок видно завжди.
3. «Отримати УДК» завжди має бейдж стану.
4. «Опублікувати зміни» рендериться лише коли є неопубліковані зміни; інакше відсутня (не disabled).
5. «Зняти з публікації» доступна лише з меню «⋯», червона, з діалогом підтвердження.
6. Платні послуги клікабельні й не сірі; усі «Скоро» — один рядок; є «Усі послуги».
7. У сайдбарі жоден пункт не обрізається «…» при ширині 264 px; «скоро»-пункти — в одній групі внизу.
8. «Вихідні дані» — однакова назва в сайдбарі, степері, H1.
9. На сторінці «Вихідні дані» одна кнопка збереження (sticky), стан «Збережено ✓» після успіху; «Зберегти ISBN» відсутня; ISBN зберігається разом із формою.
10. Для опублікованої книги показано банер про повторну модерацію; після збереження на дашборді з'являється стан «є зміни».
11. Шкала анотації оновлюється наживо, позначки 50/120/150/250 стають зеленими при досягненні; мінімум для збереження — 120.
12. Усі тексти українською; кольори/радіуси — з наявних токенів (green-600 акцент, rounded-xl картки, border-gray-200).
13. Підсвітка на «Вихідних даних»: помаранчева рамка (amber-400) = блок із незбереженими змінами (змінені поля теж з помаранчевою рамкою); червона (red-500) = блок із помилкою валідації (поле — червона рамка + текст помилки). Лічильник у нижній панелі = кількість таких блоків («у 2 блоках · 1 помилка»); «Перейти до першого» скролить до першого підсвіченого блоку, «1 помилка» — до блоку з помилкою. Підсвітка зникає після збереження (помаранчева) або виправлення (червона); у стані «Збережено ✓» підсвітки немає.

14. «Ціна»: у кожному каналі одне поле «Ваш гонорар»; заголовки колонок однакові в обох таблицях; ціна для читача перераховується наживо, у `dirty` показано стару (закреслену) і нову ціну та «було → стало» для гонорару.
15. «Ціна»: недоступний канал (KDP для цієї мови, KDP Select) — disabled із причиною в рядку; увімкнути його неможливо.
16. «Ціна»: варіанти друку видно одночасно (матриця 2×2), без прихованих вкладок; «Що відбудеться…» — у нижній панелі.
17. «Обкладинка»: статус + дві дії вгорі; превʼю е-книги й розвороту — в одному екрані на 1280 px; на розвороті є підписи частин і легенда ліній.
18. «Огляд»: кожна картка має «Змінити» на свою сторінку; ціни й прибуток — одна таблиця; магазини — іменовані чипи; УДК — один рядок «N з 4», розгортається; у UI немає шляхів до внутрішніх файлів.
19. «Огляд» (опублікована книга): є зміни з останньої публікації → змінені блоки помаранчеві + CTA «Опублікувати зміни (N)» з приміткою про повторну модерацію; змін немає → CTA відсутня.
20. Формат скрізь «Стандартний 130×200 мм» (не «Індивідуальний»).

## Знайдені баги (поточний прод)
1. **Дубль гонорару** на «Ціні» (друк): окреме поле «Ваш бажаний гонорар за примірник (ULIT)» = 150 і те саме 150 у рядку ULIT таблиці.
2. **Різна назва формату**: «Формат 130×200мм (Стандартний)» на «Ціні» vs «Індивідуальний (130×200мм)» на «Огляді».
3. **Внутрішній шлях у UI**: «Готовність до реєстрації УДК» показує «детальніше в docs/isbn-udc-requirements.md».
4. **Amazon KDP (е-книга) можна увімкнути** для мови, яку Kindle не приймає; попередження — лише дрібним помаранчевим текстом.
5. **Зміна ціни опублікованої книги без попередження**: 150 → 160 перераховує ціну (374.29 → 388.57) без індикації незбережених змін і без згадки про модерацію; кнопка «Зберегти» синя (не токен green-600).
6. Різні назви колонок у двох таблицях «Ціни» («Ваша ціна / роялті» vs «Роялті / ціна (ваша ставка)»; «Ціна за книгу в магазині» vs «Ціна в магазині»).
7. Ч/Б-варіант: поле називається «Пряма ціна за примірник, ч/б (ULIT)» (ціна, а не гонорар) — інша логіка без пояснення.

## Відкриті питання
1. Primary-колір: у формі зараз синій `--primary` (shadcn), у UI — зелений акцент. Робимо зелений primary глобально чи лише на цих сторінках?
2. Коли є зміни — чи лишати «Сайт книги» primary (як погоджено) поряд із зеленим «Опублікувати зміни»? У WF primary передано «Опублікувати зміни».
3. Що рахуємо в «N з 13 кроків» — чи входить необов'язковий УДК?
4. Які послуги просування реально доступні зараз? У сайдбарі «Замовити тираж» активний, а на дашборді «Тираж книги — Скоро». У WF «Про-акаунт» віднесено до просування — підтвердити.
5. Повні назви обрізаних пунктів сайдбару («Завантажи…», «Знайти но…») — у WF «Завантаження», «Знайти читачів».
6. Чи потрібен перелік змінених розділів («Що змінилось?») — є дані на бекенді?
7. Чи зберігати автоматично (autosave) замість кнопки — поки ні, лише явне «Зберегти зміни».
